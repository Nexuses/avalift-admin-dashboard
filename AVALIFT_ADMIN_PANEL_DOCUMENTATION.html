1. What this application is

The Avalift Admin Panel is a web dashboard used by internal operations staff (super admin, operators, and other admin roles) to run a chauffeur / taxi platform. It is not a backend. It is a React frontend that talks to a remote REST API.

From this panel, staff can:

  • View a live operations dashboard (stats, charts, scheduled rides)
  • Manage customers, chauffeurs (drivers), PDs (pickup/drop staff), organization customers, and admin users
  • Manage organizations and organization-level pricing
  • Create and monitor rides (on-demand and scheduled)
  • See nearby / available chauffeurs on a map
  • Manage vehicles, brands, and models
  • Handle wallets (customer, chauffeur, PD, admin, tips), cash, invoices, and revenue reports
  • Create coupons and coupon user groups
  • Send push notifications
  • Change password and view account details

There is no mock data layer. After login, almost every screen loads live data from the backend currently configured as:

https://api.live.avalift.ae

That host is hardcoded in src/config/apiConfig.ts. It is not read from the .env file.

7. Request / data flow

Every authenticated screen follows the same pattern.

  User opens a page (example: All Rides)
              │
              ▼
  Page / table component reads authToken from localStorage
              │
              ▼
  Calls a domain service, e.g. RideService.getAllRides()
              │
              ▼
  Service builds URL = BASE_URL + "/api/admin/get-all-rides/{page}/{limit}"
              │
              ▼
  apiGetFetcher / apiPostFetcher / fetch()
      headers: Content-Type: application/json
               Authorization: Bearer <authToken>
              │
              ▼
  https://api.live.avalift.ae  (REST backend)
              │
         ┌────┴────┐
         ▼         ▼
      200 OK     401 Unauthorized
         │         │
         ▼         ▼
   JSON → table   apiFetcher clears localStorage
   / charts       and redirects to /

Shared HTTP helpers live in src/utils/apiFetcher.ts:

  • JSON: GET, POST, PUT, DELETE
  • Multipart: POST / PUT FormData (vehicle images, documents, etc.)
  • On 401: wipe authToken, allowedOrganization, roles, permissions, isLoggedIn and send the browser to login

There is no Redux / Zustand / React Query global store. State is mostly:

  • React useState / useEffect per page
  • localStorage for session

8. Login, session, and access control

8.1 Login sequence

  1. Browser opens /
  2. App registers /firebase-messaging-sw.js
  3. Requests Notification permission → FCM device token
  4. User submits email + password on LoginForm
  5. POST {BASE_URL}/api/auth/admin-login
       body: { email_id, password, device_id: fcmToken }
  6. Backend returns token + user + roles + permissions + allowedOrganization
  7. Saved in localStorage:
       authToken
       isLoggedIn = "true"
       allowedOrganization
       roles          (JSON array)
       permissions    (JSON array)
  8. Navigate to /admin/dashboard
  9. ProtectedRoute checks isLoggedIn + authToken

Forgot password is a 3-step modal flow on the same login screen:

  1. POST /api/auth/admin-forgot-password
  2. POST /api/auth/admin-verify-otp
  3. POST /api/admin/admin-reset-password

Logged-in password change: POST /api/auth/change-password.

Logout: POST /api/auth/logout then clear storage.

A storage event listener in App.tsx keeps login/logout in sync across browser tabs.

8.2 Protected routes

src/components/ProtectedRoute.tsx only checks that isLoggedIn === "true" and authToken exist. It does not check permissions per URL. If a user knows a URL, they can open it unless the API itself rejects the call.

Menu visibility is permission-based in src/components/app-sidebar.tsx.

13. How to run locally

  1. Install Node.js (project was last run on Node 26; Vite 6 / this stack is more typically used with Node 18 or 20 LTS).
  2. In the project folder: npm i
  3. Confirm .env has a valid VITE_GOOGLE_MAPS_API_KEY if you need maps.
  4. Confirm src/config/apiConfig.ts points at the backend you want (live vs stage vs dev).
  5. npm run dev → open http://localhost:5173/
  6. Log in with an admin account that exists on that backend.

Need enough free disk space before npm i. A previous install failed with “no space left on device”, which left react-icons incomplete and crashed Vite with a missing lib/index.mjs.

14. Important engineering notes

  1. Frontend only. Databases, matching, payments server, and mobile apps are outside this repository.
  2. Hardcoded API host. All business data comes from BASE_URL in apiConfig.ts. Recommended improvement: VITE_API_BASE_URL in .env.
  3. Secrets in source. Firebase web config / VAPID key are in repo files. Google Maps key is in .env (Vite exposes any VITE_ key to the browser anyway).
  4. Auth model. JWT-like token in localStorage. Sidebar hides menus by permission; routes are not permission-gated individually.
  5. Org scoping. allowedOrganization of * or 1 = platform admin. Any other ID = single-organization operator experience.
  6. UI mix. Primary design system is shadcn/Radix + Tailwind; Ant Design is also present. Icons mix lucide-react and react-icons.
  7. No dedicated test suite in package.json (no Jest / Vitest / Cypress scripts).
  8. Empty routes in App.tsx (settings, roles, etc.) are stubs.
